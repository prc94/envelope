## 1. Experiments and spikes (Windows VM as `envelope`; harness checks)

Their outcomes are recorded in design.md before the dependent tasks start; the specs already allow each negative outcome.

- [x] 1.1 E1a — console-less start: start the outer `cmd /d /v:on …` wrapper with `DETACHED_PROCESS` instead of `CREATE_NO_WINDOW` and check (a) whether console-reading prompts (`set /p`, `choice`, a `getpass` script, an `ssh` password prompt, a `git` credential prompt) fail fast, (b) whether the S1 UTF-8 path (`chcp 65001`, Cyrillic output from pwsh, Windows PowerShell and a native tool) still works, (c) whether console children flash visible windows or leave the process group; verify by recording the outcomes and the chosen approach in design B13
- [x] 1.2 E1b — console text: prototype a helper (`python -I -S -c`, `DETACHED_PROCESS`) that attaches to a run's hidden console through a live job member and reads the visible screen text (`GetConsoleScreenBufferInfo`, `ReadConsoleOutputCharacterW`) while an `ssh` password prompt and a `getpass` prompt wait; verify by recording whether the prompt text is read reliably, and envelope's own process is unaffected, in design B12
- [x] 1.3 E2 — graceful stop: prototype the ctrl-break helper (attach through any live job member, `SetConsoleCtrlHandler(NULL, TRUE)`, `GenerateConsoleCtrlEvent(CTRL_BREAK_EVENT, root pid)`) against commands started through envelope's real launch chain in cmd, pwsh, Windows PowerShell and git-bash, including batch wrappers (`npm.cmd`/`npx.cmd` running a Node server with and without a SIGBREAK handler, a `.bat` running a long command), a .NET generic-host app if available, a plain Python script, and a run whose root process already exited; verify by recording which targets receive the event, whether cmd prompts "Terminate batch job", and the resulting Windows stop mode (graceful or forced) in design B7
- [x] 1.4 W3 — port table: call `GetExtendedTcpTable(TCP_TABLE_OWNER_PID_LISTENER)` for `AF_INET` and `AF_INET6` via ctypes as the standard user `envelope` over SSH and map a test server's PID to its job; verify by recording the result (and any access error) in design B5
- [x] 1.5 Harness check: with a throwaway MCP stub, confirm that Qwen Code 0.24.5 and OpenCode 1.18.32 send a `progressToken` on `tools/call`, that a 90-second call with 5-second progress completes in both, and that a 400-second call completes in OpenCode and in Qwen Code (under its 10-minute limit); verify by recording the observed `_meta` and outcomes in design B2
