## Context

Greenfield project; see proposal.md for motivation and scope. The approach is shaped by constraints and findings established during exploration:

- **Corporate hosts block user-space binaries** (AppLocker/WDAC exe and script rules, possibly DLL rules), place PowerShell in Constrained Language Mode (CLM), enforce ExecutionPolicy via GPO, and run EDR. Approved interpreters: Python up to 3.12.13, Node 25.3.0. OpenCode (a compiled binary) cannot run there; Qwen Code (Node ≥22) can.
- **MCP landscape (Sept 2026):** spec `2026-07-28` is stateless (no `initialize`, `server/discover`, versions in `_meta`, server-minted handles for cross-call state, Tasks moved to an extension, MRTR replaces server-initiated elicitation, logging deprecated). Real clients still speak `2025-11-25`.
- **Harness behavior (read from source, commits `sst/opencode@610df0b`, `QwenLM/qwen-code@64ac2fa`):**

  | | OpenCode | Qwen Code |
  |---|---|---|
  | MCP client | TS SDK v1.29, `2025-11-25` | TS SDK v2 client |
  | `structuredContent` | ignored when text content exists | JSON-stringified and appended to text |
  | Request timeout | 30 s, reset on progress | 10 min idle, reset on progress |
  | Own truncation | 2000 lines / 50 KB | 1000 lines / 25,000 chars |
  | Server instructions | injected into system prompt | collected per server |
  | Elicitation / tasks | not advertised | not advertised |
  | Tool loading | eager, named `<server>_<tool>` | may defer behind `tool_search` |

- **Open-model tool-calling quirks:** Qwen and GLM frequently stringify nested objects and send numbers/booleans as strings.
- **Prior art lessons:** win-cli-mcp-server (archived) and Desktop Commander use bypassable string blocklists; Codex unified exec head/tail-truncates with no recovery path; Claude Code's git-bash support broke repeatedly by shelling out to `cygpath`.

## Goals / Non-Goals

**Goals:**
- One portable artifact that behaves identically on Linux, macOS and Windows, including CLM/AppLocker hosts.
- Model-facing results that are complete in text form and small enough to never trigger harness-side truncation.
- Guaranteed cleanup of every spawned process, including when envelope itself dies.
- Internal seams (policy decision, spool format, request model) that later phases extend without redesign.
- De-risk the Windows/corp unknowns with time-boxed spikes before building on them.

**Non-Goals (design level):**
- No persistent shell sessions; no PTY; no background processes in this change (P3).
- No attempt to parse commands for security in this change (P4).
- No HTTP transport, no Tasks extension.
- Not a sandbox: the policy layer is a guardrail, never an isolation boundary.

## Decisions

### D1. Python ≥3.12, standard library only, zipapp distribution
Envelope's core job is process control, and its hardest target is Windows. The stdlib plus `ctypes` gives Job Objects (kill-on-close), `CREATE_NEW_PROCESS_GROUP`/`CTRL_BREAK_EVENT`, ConPTY (later), `winreg`, all OEM code pages (`codecs`), `pty` on POSIX, `prctl` on Linux and `tomllib` — with no native code of our own. Distribution is `envelope.pyz` built with `zipapp`; optional PyPI package for home use.

*Alternatives:* **Node** (single `.mjs` bundle with official MCP SDK v2 and WASM tree-sitter parsers) — rejected because Node 25.3 has no FFI (`node:ffi` is experimental and Node 26+ only), leaving Windows tree-kill to `taskkill`, no crash-safe cleanup, no graceful Windows stop, no PTY. **Go/Rust native binary** — blocked by application control. **Official Python MCP SDK** — pulls `pydantic-core`, `rpds-py`, `pywin32` (native), which WDAC may block.

### D2. Own MCP protocol layer (stdio, server side only)
A small JSON-RPC 2.0 layer: newline-delimited framing, request dispatch on an asyncio loop, `initialize`/`initialized`/`ping` for `2025-11-25`, `server/discover` and `_meta` handling for `2026-07-28`, `tools/list`, `tools/call`, outgoing `notifications/progress`, incoming `notifications/cancelled`. Version is resolved per request: `_meta["io.modelcontextprotocol/protocolVersion"]` if present, else the version negotiated by `initialize`, else `2025-11-25`. Results always carry `resultType: "complete"` (older clients ignore unknown fields). Interoperability is verified against OpenCode and Qwen Code in P0 (spike S5) and continuously in CI.

*Alternative:* vendor the official SDK — rejected (native dependencies, size, far more surface than needed).

### D3. Tool surface: `run` and `output`, flat and forgiving
Two tools in P1; P3 adds `input` and `stop` (surface "B"), with variants A (`run`+`input`) and C (six explicit tools) evaluated in P2. Schemas are flat; `env` is the only object-ish parameter and also accepts `KEY=value` lines. A coercion layer normalizes arguments before validation (see mcp-server spec) and records every coercion — this doubles as a P2 metric of per-model schema trouble. Descriptions include the words shell/command/terminal and the detected shell list so deferred-loading clients find them.

### D4. Text-first results; metadata-only `structuredContent`
OpenCode shows only text; Qwen Code shows text plus stringified `structuredContent`. Therefore text carries everything (header, body, notes), and `structuredContent` carries metadata only to avoid double token cost. This intentionally departs from the MCP recommendation that text mirror the serialized structured content. Default budget 12,000 chars / 400 lines keeps results under both harnesses' truncation thresholds (25,000 chars / 1,000 lines is the tighter). Head/tail split favors the tail (roughly 1/3 head, 2/3 tail) because errors and summaries usually come last. Header format: `exit 1 | 2.3s | git-bash | cwd C:\src\app`.

### D5. One process per call, explicit `cwd`
Matches both harnesses' native shell tools (what models are trained on) and the stateless direction of MCP. Persistent sessions are deferred to P3b and only if P2 shows demand.

### D6. Script delivery per shell
- **bash family:** write the script to a spool-dir file and run `bash <file>` — the file is read as data, so noexec mounts and AppLocker do not apply, no command-line limit, and stdin remains free for caller input.
- **PowerShell:** pass the script as data and execute it as a script block. Candidates, decided by spike S1: (a) data file with a non-script extension read via `Get-Content -Raw` then `[scriptblock]::Create` and invoke; (b) length-framed script on stdin followed by caller stdin. Must work in pwsh 7 and 5.1, under CLM and with AMSI, and must not use `-EncodedCommand`, `-ExecutionPolicy Bypass` or `Invoke-Expression` (EDR heuristics, GPO override). A fixed prologue sets `$ProgressPreference='SilentlyContinue'`, UTF-8 `[Console]::OutputEncoding`, `$PSStyle.OutputRendering='PlainText'` (pwsh 7), and an epilogue maps `$LASTEXITCODE`/`$?` to the exit code and flags non-terminating errors. **Outcome (S1):** see D14 — nested-cmd `-Command` by default, data file only for >32 K scripts in FullLanguage.
- **cmd:** `cmd.exe /d /s /c "chcp 65001>nul & <command>"`; commands over 8,191 characters are rejected with guidance (cmd has no safe data-file path that avoids AppLocker `.cmd` script rules). **Outcome:** the single-cmd form does not work under `CREATE_NO_WINDOW`; see D14 (nested cmd).
- **Custom shells:** argument template with `{script}` placeholder, optional `{file}` form.

### D7. Process containment and cleanup
- **Windows:** at startup envelope places itself in a Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` (crash safety: when envelope dies, the OS kills everything in the job; nested jobs work on Windows 8+ even if the client already put envelope in a job). Each run gets its own nested job so a single command's tree can be killed (`TerminateJobObject`). Children are created with `CREATE_SUSPENDED`, assigned to the run's job, then resumed, closing the race where a child spawns grandchildren before assignment; spike S2 confirms the resume mechanism (`NtResumeProcess` vs. owning `CreateProcessW` via ctypes). Children also get `CREATE_NO_WINDOW` (no console flashes when envelope has no console) and `CREATE_NEW_PROCESS_GROUP` (enables `CTRL_BREAK_EVENT` for P3 graceful stop).
- **Linux:** each command starts in a new session (`setsid`) and is killed with `killpg`; envelope marks itself a child subreaper (`PR_SET_CHILD_SUBREAPER`) so descendants that escape the process group are re-parented to envelope and can be tracked and killed; commands are started through a tiny launch shim that sets `PR_SET_PDEATHSIG=SIGKILL` so the tree dies if envelope does.
- **macOS:** new session + `killpg`; crash safety via the launch shim watching envelope's PID (kqueue `NOTE_EXIT`) and killing its process group. Spike S3 validates, or the spec's documented-limitation branch applies.

*Alternative:* `taskkill /T /F` plus descendant snapshots — misses re-parented orphans and offers no crash safety.

### D8. Shell discovery without spawning shims
Shells are resolved to real executables (Node-style `.cmd` shims rejected, matching the spec). git-bash: registry `HKLM/HKCU\SOFTWARE\GitForWindows\InstallPath` → `git.exe` on PATH → standard directories; use `<Git>\bin\bash.exe` (the launcher that sets `MSYSTEM` and PATH), never `System32\bash.exe`. Probes run in parallel with a 5 s overall budget. The "command available in another shell" hint uses a filesystem PATH/PATHEXT lookup against each shell's effective PATH — no extra processes. Path translation between Windows and MSYS forms is implemented in-process (never `cygpath`). MSYS automatic argument conversion is left at Git's default (models expect standard git-bash behavior); revisit after P2.

### D9. Output pipeline and spool format
Readers for stdout/stderr push chunks into a single ordered event stream tagged by stream and arrival sequence. The spool is an append-only file of framed chunks (stream, sequence, timestamp, bytes) plus a line-offset index built incrementally, so `output` can serve any line range or grep without re-reading from the start, and P3 can add ring-buffer retention and per-line timestamps without format changes. Rendering is lazy and applies: decode (UTF-8 → UTF-16 detection → console code page for cmd/Windows PowerShell) → ANSI strip → `\r`/backspace resolution → repeat folding → budgeted head/tail. Default rendering interleaves streams in arrival order, prefixing stderr lines with a marker; `output(stream=...)` gives per-stream views. Handles are `out_<8 hex>`.

### D10. Policy seam
A pure function `decide(request, config) -> Decision(verdict, rule_id, reasons)` invoked by a single execution gateway that both `run` and (future) `input` must pass through. P1 rules: allowed shells, cwd roots, max length. `ask` has no approval channel in P1 (no client elicitation); it is rendered as an actionable tool error. Audit-only mode computes and logs without enforcing. P4 inserts parsers/fact extraction/layered rules behind the same function; MRTR elicitation is used when a client advertises support.

### D11. Configuration in TOML
Read with `tomllib`; per-user locations: `%APPDATA%\envelope\config.toml`, `~/Library/Application Support/envelope/config.toml`, `$XDG_CONFIG_HOME/envelope/config.toml`. TOML is also the planned format for P4 rules (comments, human editing). Env vars `ENVELOPE_<KEY>`, flags `--<key>`. Spool and audit under the OS cache/state directories.

### D12. Proposed defaults (accepted during exploration, all configurable)
Windows default shell git-bash → pwsh → powershell → cmd; interleaved streams with stderr marked; timeout 120 s (max 3,600 s); concurrency 8; progress every 5 s; spool 64 MiB/run, 1 GiB total, 24 h retention.

### D13. Testing strategy
- Unit: coercion, decoding, cleanup, truncation, rendering, hints, path translation, config validation, policy.
- Integration (real shells per OS): execution, timeouts, cancellation, tree kill, crash-safety (kill envelope, assert children gone), encodings, large scripts.
- Protocol: scripted JSON-RPC client for both protocol versions; MCP conformance suite if it can drive stdio servers.
- Interop: OpenCode and Qwen Code headless against envelope (smoke level in P1; full evaluation is P2).
- Corp simulation: CLM on Windows CI via the `__PSLockdownPolicy=4` machine environment variable; AppLocker scenarios verified manually on a corp machine using `doctor`.
- CI matrix: {Linux, Windows, macOS} × Python {3.12, 3.13, 3.14}.

#### Spike outcomes

- **S3 (Linux verified 2026-09-23, macOS pending):** launch shim `python -I -S -c <envelope/execution/_shim.py> STATUS_FD PARENT_PID -- ARGV`, started by envelope in a new session. The *shim* (not envelope) is the child subreaper and carries `PR_SET_PDEATHSIG=SIGTERM`, so orphans (including `setsid` escapees and double-forked daemons) re-parent to it; on SIGTERM (timeout, cancel, shutdown) or parent death it SIGKILLs every descendant found by walking `/proc` until none remain. The shim reports `pid`/`exit`/`signal`/`error` on a status pipe, which also carries exec failures. When the shell has exited and stdout/stderr reached EOF, envelope terminates any remaining descendants (detached leftovers such as `git gc --auto`) instead of waiting for them. macOS: kqueue `NOTE_EXIT` watch on envelope's PID plus `killpg` (descendants that `setsid` away escape — documented limitation until verified). Measured on Linux/CPython 3.12: 5-process tree incl. a `setsid` escapee killed on shim SIGTERM and on SIGKILL of the parent; shim overhead ≈ 15 ms per call (< 50 ms). Script: `scripts/spikes/s3_posix.py`. Hardening found in integration testing: the shim keeps SIGTERM blocked until its wait loop is entered and handles it only once (a second SIGTERM during the kill otherwise aborted it), and resets SIGPIPE/SIGXFSZ to default before `execv` (Python ignores them at startup; `subprocess` restores them, a bare `fork`/`execv` does not).

## Risks / Trade-offs

- [Own protocol layer drifts from spec] → Keep it minimal; version-dispatch table; protocol tests per version; interop tests against two real clients in CI; track spec changelog per release.
- [PowerShell delivery blocked by CLM/AMSI/EDR on some corp hosts] → Spike S1 first; `doctor` smoke tests expose which path works; fallback to pwsh's documented `-Command -` stdin mode with its multi-line caveats.
- [Job Object assignment race or nested-job failures] → Suspended creation (S2); `doctor` reports whether envelope's own job was established; degrade to per-run jobs with a stderr warning.
- [macOS crash safety unachievable cleanly] → Spec allows documented limitation; shim-based watchdog as best effort.
- [Launch shim adds latency on POSIX] → Measure in S3; skip the shim on Linux if subreaper plus PDEATHSIG via another path suffices.
- [Environment scrubbing removes a variable a command needs] → Patterns configurable; explicit `env` bypasses scrubbing; audit log records removed names (not values).
- [Metadata-only `structuredContent` departs from MCP SHOULD] → Deliberate; text is complete; revisit with per-client profiles later.
- [Budget too small for some tasks / too large for small-context models] → Configurable; P2 evals tune the default; `output` recovers anything omitted.
- [EDR flags many short-lived shells] → Plain command lines, no encoded commands, no `iex`; documented for corp admins.
- [Python version drift on Windows corp hosts (3.12 security releases ship without Windows installers)] → Floor is `>=3.12`; `doctor` reports the interpreter; avoid 3.13+ APIs.

## Migration Plan

Greenfield; no migration. Release = versioned `envelope.pyz` artifact (plus optional PyPI package). Users register it in their MCP client as `python /path/to/envelope.pyz`. Rollback = previous artifact.

## Roadmap (subsequent changes)

Each phase is proposed as its own OpenSpec change just before it is built (decided 2026-09-24), not in advance: later phases depend on earlier results (P2 chooses the tool surface and tunes defaults for P3/P4), and their deltas modify P1 capabilities, which now exist in `openspec/specs/` since `add-envelope-core` is archived (2026-09-25) with six tasks knowingly left open — see **P1-remainder** below, not carried as unfinished work on this closed change. P2 is next. Windows test platform for the remaining P0/P1 work: `docs/windows-test-vm.md`.

- **P1-remainder — macOS support and CI:** propose the six tasks `add-envelope-core` closed without (2.3/6.5 macOS POSIX containment, 12.2-12.4 CI pipeline, 13.1's macOS/CI portions) as their own change once a macOS host and a CI platform decision (GitHub Actions vs. self-hosted Forgejo runners — still open, see below) are available. Until then: macOS crash-safety is an explicitly documented limitation (matching 13.1's own stated bar), and every other capability is verified manually (Linux: 164 tests; Windows: extensively, live, under real AppLocker/WDAC/GPO enforcement — see the spike notes above) rather than by CI.

- **P2 — Evaluation harness:** YAML task suite (basics, large output, long-running, errors/hints, large scripts, PowerShell, cmd, git-bash, simulated corp restrictions) with checker scripts; headless runners for OpenCode and Qwen Code × Qwen/DeepSeek/GLM via OpenRouter with pinned providers; baseline against each harness's native shell tool; metrics (success, invalid calls, coercions, turns, output tokens, truncation recovery, timeouts); A/B of tool surfaces A/B/C; results feed defaults and descriptions. Starting point from the S5 interop runs (2026-09-24): `scripts/interop.py` (fixed per-harness projects, envelope audit log as ground truth, harness native shell tool disabled; lacks multi-trial repeats, pinned providers, baselines, token/turn accounting). Candidate models: DeepSeek V4 Flash 0731, Qwen3.8 Flash, GLM 5.3 Flash. Runner requirements learned: pin OpenCode's `small_model` and pass `--dir`; select Qwen Code models via `OPENAI_*` env (it silently substitutes models for `qwen/…` ids in `modelProviders`) and verify the served model from `~/.qwen/usage/`; kill harnesses by process group; per-run timeouts ≥ 10 min; score from the audit log, never from the final answer alone. Additional metrics: tool skipped (model answered without calling `run`), invented handles, malformed arguments (e.g. GLM's stray `}"`), harness stalls (Qwen Code + GLM after `tool_search`, excluded from envelope scoring but reported), and whether deferred loading (`tool_search`) finds `run` on the first query. Multiple trials per cell are required: single runs flipped between pass and fail for GLM.
- **P3a — Background & interactive:** `wait_s` on `run` returning process handles; `wait_for` conditions (`exit`, `regex:`, `port:`, `idle:`) on run/input/output; read cursors (new output since last read); named handles with idempotent start and `restart`; `input` (text and control keys) and `stop` (signal, grace, escalation; Windows graceful stop per spike) tools; status listing with state, uptime, last line and listening ports; waiting-for-input detection; completion notices piggybacked on later results; lifetime/idle limits and LRU cap; background-specific hints (port in use with owner, TTY required, password prompt); every `input` to shells/REPLs passes through the policy seam.
- **P3b — Extensions:** multi-handle wait (all/any), per-line timestamps, opt-in detached processes with an on-disk registry for re-attach after restart.
- **P4 — Security classifier:** conservative bash parser and PowerShell tokenizer with "opaque" fallback (never auto-allowed); fact extraction (commands, args, pipes, redirects and written paths, substitutions, cd targets, network use, privilege escalation, opaque constructs); prefix/regex/path/fact/pipeline rules; allow/ask/deny with most-restrictive-wins and justifications; layered config where project files may only tighten; inline rule tests; `policy test` explain command; approval fallback without elicitation and MRTR elicitation where supported; pluggable external classifier hook.
- **Later:** Streamable HTTP transport, MCP Tasks extension, output handles as resources / `resource_link`, per-client rendering profiles, PTY (POSIX `pty`, Windows ConPTY via ctypes), OpenTelemetry.
